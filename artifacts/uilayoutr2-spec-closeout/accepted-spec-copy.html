8. Additional mandatory non-runtime frames

No-project / first-run frame: viewport remains dominant; New Project choice is centered over the live viewport. It does not change the binding right-host geometry because the editor host is absent before a project choice is made.
Mirrored-zone frame (OQ-05): mirror the leading/trailing edge zones as a future handedness preference. This is a specification reservation only; implementation remains deferred to UI-PREF1. The current accepted default remains right-side contextual host.
Load variant: one expanded mock page reserves placeholders for: file bar + gear in top-left; Objects hierarchy + multi-select checkboxes; Sketch rail (tools + dimensions + constraints); operation tree; UV tab; export screen. These placeholders are capacity probes, not MVP controls. Nothing unimplemented is authorized to appear in the current runtime. The accepted right-host width may be reconsidered by the future CAD-R0-UX stage if the Sketch vocabulary proves it cannot fit without violating ≥48 dp targets or viewport dominance.

9. Acceptance rules for UI-LAYOUT-R2 closeout

  1. Use this file as the independent expected geometry. Do not derive expected values from implementation resources or runtime bounds.
  2. For every state and cell, every persistent element shown here has a declared rectangle or an explicit Absent state.
  3. For elements outside the opened Exact/Details surface, opening and closing yields Δ resting bounds = 0 dp.
  4. Within each cell, right-host top/right/width are invariant across every listed state, including Exact+IME.
  5. Overlay screenshot vs this mock: each binding anchor deviation ≤ 4 dp.
  6. Every visible user-operated target is ≥ 48 dp hit area, including font scale 1.3 and constrained-height states.
  7. Static closeout uses screenshots + overlays. Video is supplementary for gesture/timing only.
  8. No new motion/morph, JNI/domain/transform/sculpt semantic change is authorized by this specification.
